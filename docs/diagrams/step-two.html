One Door, Eight Pairs

Step 1 fetched one pair on one timeframe, with both written into the code. Step 2 makes that a list you edit, hides the feed behind one interface so a second one can be added without a rewrite, and solves a timing problem that is worse than it first looked.

The problem nobody would have found by reading

Twelve Data allows 8 requests a minute on the free plan. That sounds generous until you notice when our requests want to happen.

Moment What closes at once Requests Limit
Every hour the 1-hour 8 8
Every 4 hours the 1-hour and the 4-hour 16 8
21:00 UTC daily 1-hour, 4-hour and the day 24 8
Friday 21:00 UTC 1-hour, 4-hour, the day and the week 32 8

Friday at 21:00 UTC is the worst moment in the week, and it is not a coincidence — 21:00 UTC is 17:00 in New York, which is where the hour, the day and the week all end at once. Every timeframe we watch finishes on the same second.

The daily budget is not the problem. Eight pairs use about 250 of the 800 allowed in a day. It is the burst, not the total.

Fire at once, or spread out

One minute of Friday evening, drawn twice. Each mark is a request; the dotted line is what the plan allows.

Why this would not look like a bug

A refused request does not crash anything. It comes back as an ordinary reply saying too many requests.

So the bot carries on, and the candles it did not get are just missing — quietly, on the busiest close of the week.

Waiting costs nothing

We do not need the candle instantly. We need it soon — and four minutes after a Friday close is soon.

The alternative is paying $79 a month for a limit we do not otherwise need.

What gets built, in order

The pairs become a file you edit

config/symbols.toml replaces the constants at the top of settings.rs. One entry per instrument, and the things that differ between them live on the entry.

Gold is quoted to 2 decimals, EURUSD to 5, USDJPY to 3. That is not a detail — print five decimals on gold and a signal reads like a debug dump.

One door every feed hides behind

An interface with one job — give me the last N candles of this pair on this timeframe — and Twelve Data behind it.

This goes in now, not later. OANDA is already planned. Adding the door afterwards means unpicking it out of every line written in between, and nothing outside that one file should ever know which feed you use.

A queue, not a burst

Everything due at a close goes into a list, and the list is worked through one request every seven seconds. Never more than eight in any minute, whatever lands at once.

Cheap to build now. Painful to retrofit once four timeframes and eight pairs are all calling the feed directly.

Know which minute it is

The bot has no clock today — you run it and it exits. It needs to wake at each close, work out which timeframes just finished, and queue only those.

At 22:00 UTC that is the 1-hour only. At Friday 21:00 it is all four. Same code, different answer.

The file, as it will look

Nothing tunable stays in the code. That is a rule in CLAUDE.md, and settings.rs broke it on purpose while there was one pair. 

# config/symbols.toml

[[symbol]]
name   = "XAU/USD"
digits = 2                 # gold is quoted to two. The feed sends five.

# It shuts 17:00–18:00 New York, every weekday. Measured in the real
# export, not assumed — the file stops at 20:45 UTC and restarts at 22:00.
nightly_break_minutes = 60

[[symbol]]
name   = "EUR/USD"
digits = 5
nightly_break_minutes = 0  # spot forex never shuts mid-week

What moves out of the code

SYMBOL, DIGITS, INTERVAL, HISTORY — all four leave settings.rs, and the file goes with them.

What stays in code is the meaning: that digits control rounding, that a nightly break is not a fault.

What it unlocks later

The weekend-candle rule and the nightly break both need to know which instrument before they can be applied.

Neither can be written until this file exists, which is why it comes before the history scan.

Done when

It runs a full trading day without missing a candle — including one Friday 21:00 UTC, which is the moment that breaks it if anything is going to.

And adding a pair is one entry in a file, with nothing rebuilt and no code touched.

This is a plan, not a result. The request numbers are arithmetic against a published limit, and the 17:00 New York boundary was measured against the real feed. Whether the queue holds up on a live Friday is something only a live Friday will say.
