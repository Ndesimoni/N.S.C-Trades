Phase 0 · the lookahead guard

The clock, not the stamp

Every candle in this project is labelled with the time it opened. A 4-hour candle that runs 21:00 to 01:00 is labelled 21:00 — and so is every swing it confirms. But nobody knew what that candle would do until 01:00. Judge by the label and the backtest reads four hours into the future without a single error message.

What walks through the gate

Everything the analysis reads goes through the guard, and the guard hands it back. "Check it, then use it" is two lines, and the day somebody deletes the first one the run goes quiet instead of loud.

Handed inLet through whenOtherwise
swing, timeframe the candle that confirmed it has closed run killed
level same, on the chart the level came from run killed — a level knows its own timeframe, so it needs no second argument
candle, timeframe it has closed, and is not still marked as forming run killed — a forming candle's high and low have not happened
a hand-drawn level the day it was drawn has arrived run killed — a line drawn today knows what price did last year

This was found by reading the code back, not by a failing test. Every test passed with the stamp comparison in place. Two now fail without the fix — a_four_hour_swing_is_not_knowable_until_its_candle_closes and a_fresh_smaller_swing_survives_a_bigger_bars_guard — and that was checked by putting the old code back, not assumed.

Nothing calls the guard yet. It is a gate, not a search: it only sees what walks through it. Wiring it into the run is harness.rs, and until then this page describes a rule that is ready rather than one that is running.
